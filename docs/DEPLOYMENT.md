## الخيار الأول (المفضَّل) — Firebase Hosting

**لماذا هو الأفضل لهذا المشروع؟**
المشروع أصلاً على Firebase (`stustep-4c1ea`). النطاقان `*.web.app` و
`*.firebaseapp.com` **مُصرَّحان تلقائياً** في Firebase Auth، فلا تحتاج أي
إعداد إضافي ليعمل تسجيل الدخول. وهو نفس الـ CLI الذي تحتاجه لنشر
`firestore.rules`.

```bash
# مرة واحدة
npm install -g firebase-tools
firebase login

# في كل نشر
flutter build web --release
firebase deploy --only hosting
```

**الرابط الناتج:** `https://stustep-4c1ea.web.app`

> الإعداد جاهز في `firebase.json` تحت مفتاح `hosting`.

### نشر القواعد والاستضافة معاً
```bash
firebase deploy --only hosting,firestore:rules
```

## الخيار الثاني — Vercel

Vercel لا يبني Flutter بنفسه، فتبني محلياً وترفع الناتج الجاهز.

```bash
# مرة واحدة
npm install -g vercel
vercel login

# في كل نشر
flutter build web --release
vercel --prod
```

الإعداد جاهز في `vercel.json`: يوجّه كل المسارات إلى `index.html` (لأن
التنقّل داخل Flutter لا عبر الخادم)، ويضبط التخزين المؤقت.

### 🔴 خطوة إلزامية بعد أول نشر على Vercel

**Firebase Console → Authentication → Settings → Authorized domains → Add domain**
وأضف نطاق Vercel (مثل `stustep.vercel.app`).

**بدون هذه الخطوة يفشل تسجيل الدخول بالكامل** ولن يستطيع أحد استخدام
التطبيق — وهذا أكثر خطأ يقع فيه من ينشر تطبيق Firebase على استضافة خارجية.

## اختبار محلي قبل النشر

```bash
flutter build web --release
cd build/web && python3 -m http.server 8080
# ثم افتح http://localhost:8080
```

جرّب المسار كاملاً: الدليل ← الشروط ← الأهلية ← المساعد ← «ماذا لو؟»

## تفعيل تسجيل الدخول بجوجل على الويب (اختياري)

1. **Google Cloud Console → APIs & Services → Credentials**
2. أنشئ **OAuth client ID** من نوع **Web application**
3. أضف نطاقك في **Authorized JavaScript origins**
4. أضف هذا السطر داخل `<head>` في `web/index.html`:

```html
<meta name="google-signin-client_id" content="ضع-معرّفك-هنا.apps.googleusercontent.com">
```

> `web/index.html` ملف مشترك يخصّ التطبيق كله لا موديولك. **نسّق مع الفريق
> قبل تعديله**، فهو ليس ضمن نطاق عملك.
