## 1. ماذا تم تنفيذ؟

القسم الخامس والأخير — وهو الوحيد الذي **لا يعرض بيانات، بل يُنتج قراراً**.

كل ما سبق يجيب أسئلة يعرف الطالب صياغتها: «ما هذا التخصص؟» و«هل أنا
مقبول؟». هذه المرحلة تجيب السؤال الذي **لا يعرف كيف يسأله**:
**أي تخصص يناسبني أنا؟**

```
بوابة القبول → المساعد → (شرط: شهادة محفوظة)
                            ↓
                  اختيار الاهتمامات (14 وسماً)
                            ↓
                  النتائج مرتّبة بنتيجة من 100
                     ↓                    ↓
            تفصيل النقاط لكل بطاقة   محاكي «ماذا لو؟»
```

**ثلاث شاشات + محاكٍ:**

| الشاشة | ما تفعله |
|---|---|
| `MatcherIntroScreen` | تشرح الأوزان **قبل** النتيجة، وتدير شرط وجود الشهادة |
| `InterestsPickerScreen` | اختيار من 14 وسماً باختيار متعدد |
| `MatcherResultsScreen` | كل التخصصات مرتّبة + مرشّح المؤهَّل + ملخّص |
| `WhatIfScreen` | تحريك المعدل والدرجات ورؤية ما ينفتح **فوراً** |

## 2. Architecture — التقسيم الذي جعل كل شيء ممكناً

```
   ┌──────────────── الجزء المتصل بالشبكة ────────────────┐
   │  MajorMatcherService.loadDataset()                   │
   │      خمس قراءات **بالتوازي** مرة واحدة:              │
   │      departments · guides · colleges                 │
   │      · requirements · gradeBands                     │
   │                      ↓                               │
   │              MatcherDataset (في الذاكرة)             │
   └──────────────────────┬───────────────────────────────┘
                          ↓
   ┌──────────── 🟢 الجزء الخالص (بلا شبكة) ──────────────┐
   │  rank(input, dataset) →  MatcherOutcome              │
   │      لكل قسم:                                        │
   │        requirements.effectiveFor(departmentId)       │
   │            ↓                                         │
   │        EligibilityEvaluator.evaluate()               │
   │            ↓                                         │
   │        MatcherScoring.breakdown()                    │
   │            ↓                                         │
   │        MajorSuggestion (نتيجة + تفصيل + أهلية)       │
   │      ثم فرز تنازلي بالنتيجة                          │
   │                                                      │
   │  simulate(...) → rank() مرة ثانية بشهادة معدَّلة      │
   │                → WhatIfOutcome.compare(before, after) │
   └──────────────────────────────────────────────────────┘
```

**هذا التقسيم ليس ترفاً معمارياً.** هو ما جعل ثلاثة أشياء ممكنة:

1. اختبار أعقد خوارزمية في المشروع بـ31 اختباراً في أقل من ثانية بلا إنترنت.
2. تشغيل المحاكي **عشرات المرات في الثانية بصفر قراءة إضافية**.
3. تثبيت نتائج الاختبار عبر `referenceYear` بدل اعتمادها على السنة الحالية.

## 4. الخوارزمية — معادلة معلنة لا حدس

### الأوزان (مجموعها 100)

| المكوّن | الوزن | كيف يُحسب |
|---|---|---|
| تطابق الاهتمامات | **60** | مزيج: التغطية 0.75 + الدقة 0.25 |
| ملاءمة المعدل | **25** | مؤهَّل 25 · قريب 12.5 · غير مؤهَّل 0 |
| توافق الشهادة والمسار | **10** | شرطان مستقلان بوزن متساوٍ (5 + 5) |
| اكتمال بيانات الدليل | **5** | مكتمل 5 · ناقص 2 · غائب 0 |

### لماذا نمزج التغطية بالدقة؟

**التغطية** = كم من اهتمامات الطالب يلبّيها هذا التخصص؟
**الدقة** = كم من وسوم التخصص تخصّ الطالب فعلاً؟

```dart
final coverage  = matched.length / studentInterests.length;
final precision = matched.length / tagSet.length;
final blended   = coverage * 0.75 + precision * 0.25;
```

لولا الدقة، لكان تخصص وسم نفسه بالاهتمامات الأربعة عشر كلها يحقق **تغطية
كاملة لكل طالب** ويتصدّر القائمة دائماً. الدقة بوزن الربع تعاقب هذا التوسيم
المفرط دون أن تطغى على المقصد الأساسي وهو خدمة اهتمام الطالب.

### نقاط المعدل مشتقّة من محرّك الأهلية لا محسوبة من جديد

```dart
static double gpaFitScore(CertificateEligibility eligibility) {
  if (eligibility.isEligible) return MatcherWeights.gpaFit;
  if (eligibility.isBorderline) return MatcherWeights.gpaFit / 2;
  return 0;
}
```

المحرّك هو **المرجع الوحيد** للأهلية. أي منطق موازٍ كان سيسمح بأن يتناقض
ترتيب الاقتراح مع شارة الأهلية المعروضة على البطاقة نفسها — وهو أسوأ ما
يمكن أن يحدث لثقة الطالب بالنتيجة.

### اكتمال الدليل ليس حكماً على التخصص

هو حكم على **جودة بياناتنا عنه**. تخصص بلا دليل لا نستطيع أن نشرح للطالب
لماذا يناسبه، فلا يصحّ أن يتصدّر تخصصاً موثّقاً بالكامل عند تساوي البقية.

## 5. محاكي «ماذا لو؟» — الميزة المحورية

### المشكلة

المراحل 3 و4 و6 تجيب أسئلة عن **الماضي والحاضر**. لكن الطالب الذي علم أنه
غير مؤهل **لا يملك تغيير معدله الآن** — فما فائدة المعلومة؟

### الحل

شاشة تجيب سؤالاً مختلفاً تماماً: **«ماذا أفعل؟»**

الطالب يحرّك شريط معدله درجتين، فيرى فوراً:
- كم فرصة كانت لديه وكم صارت
- **أسماء التخصصات التي انفتحت له بالضبط** — لا رقماً مجرداً
- ما يخسره لو نزل معدله

```dart
WhatIfOutcome simulate({...}) {
  final modified = rank(
    input: input.copyWith(certificate: modifiedCertificate),
    dataset: dataset,          // نفس البيانات — صفر قراءة جديدة
  );
  return WhatIfOutcome.compare(before: baseline, after: modified);
}
```

### تفصيلة دقيقة: أشرطة المواد

تظهر **للمواد التي أدخل الطالب درجتها فقط**. لو عرضنا شريطاً لمادة لم
يُدخلها، لكان تحريكه من صفر يعني ضمناً أنه أدخلها بدرجة صفر — فيتحوّل سبب
الرفض من «معلومة ناقصة» إلى «درجة راسبة»، وهما حالتان مختلفتان تماماً في
تفسير النتيجة.

## 6. القرارات الهندسية

### القرار 1 — فصل التحميل عن الترتيب

**Decision:** `loadDataset()` تلمس الشبكة، و`rank()` دالة خالصة لا تعرفها.

**Reason:** بلا هذا الفصل يستحيل أمران معاً: اختبار الخوارزمية آلياً،
وتشغيل المحاكي فورياً. كلاهما نتيجة مباشرة لقرار واحد.

**Alternative:** خدمة واحدة تجلب وترتّب — أقصر بسطرين، وتقتل الميزة
المحورية والاختبار معاً. مرفوض.

### القرار 2 — القراءات الخمس بالتوازي

**Decision:** إطلاق الخمسة ثم انتظارها، لا `await` متتالية.

**Reason:** لا يعتمد أي منها على نتيجة الآخر، فالتسلسل كان يجمع أزمنتها بلا
أي فائدة — تأخير محسوس عند فتح أهم شاشة في الموديول.

### القرار 3 — عرض كل التخصصات لا المؤهَّل منها فقط

**Decision:** تُعرض كلها مع شارة أهلية ملوّنة ومرشّح اختياري.

**Reason:** إخفاء غير المؤهَّل يحرم الطالب من معرفة أن **أقرب أحلامه إليه
يبعد ثلاث درجات**. الشارة تمنع الالتباس، والمرشّح يترك له الخيار.

**Alternative:** إخفاء غير المؤهَّل — قائمة أنظف، ومعلومة أهم مفقودة. مرفوض.

### القرار 4 — لا اختفاء صامت

**Decision:** الأقسام التي لم تُنشر شروط كليتها تُستبعَد **مع إبلاغ صريح
بعددها** في شريط الملخّص.

**Reason:** الاختفاء الصامت يوهم الطالب بأن الخيار غير موجود أصلاً. الفرق
بين «لا يوجد» و«لا نعرف بعد» جوهري في قرار مصيري.

### القرار 5 — عرض الأوزان قبل النتيجة لا بعدها

**Decision:** `MatcherWeightsCard` في شاشة البداية.

**Reason:** الأوزان المعروضة بعد النتيجة تبدو تبريراً، وقبلها تبدو تعاقداً.
والفرق في ثقة الطالب كبير.

### القرار 6 — النتيجة سجل تاريخي لا يُحرَّر

**Decision:** `matcher_results` تسمح بالإنشاء والقراءة والحذف — **لا التعديل**.

```
allow read, create, delete: if isOwner(userId);
allow update: if false;
```

**Reason:** النتيجة صورة للحظة معيّنة بمدخلات معيّنة. تعديلها يجعلها تكذب
على صاحبها لاحقاً.

### القرار 7 — `referenceYear` قابلة للحقن

**Decision:** كل دالة تحسب عمر الشهادة تقبل سنة مرجعية اختيارية.

**Reason:** بدونها تتغيّر نتيجة الاختبار بتغيّر السنة الميلادية، فينكسر
الاختبار في أول يناير بلا أي تغيير في الكود. اختبار يعتمد على الساعة ليس
اختباراً.

## 8. أسئلة المناقشة المتوقعة

**س: كيف رتّبت النتائج؟ ولماذا أثق بالترتيب؟**
بمعادلة معلنة من أربعة مكوّنات مجموعها 100، والأوزان **تُعرض للطالب قبل
النتيجة لا بعدها**. وكل بطاقة تفتح تفصيل نقاطها. الترتيب الذي لا يستطيع
صاحبه شرحه ليس خوارزمية بل حدس.

**س: لماذا الدقة مع التغطية؟**
لأن تخصصاً يوسم نفسه بكل الاهتمامات كان سيتصدّر لكل طالب. الدقة بوزن الربع
تعاقب التوسيم المفرط دون أن تطغى على اهتمام الطالب.

**س: كم قراءة من Firestore يستهلك المساعد؟**
خمس قراءات مرة واحدة عند فتحه، منفَّذة بالتوازي. بعدها كل إعادة ترتيب —
بما فيها كل حركة في المحاكي — تتم في الذاكرة بصفر قراءة إضافية.

**س: لماذا تعرض تخصصات الطالب غير مؤهل لها؟**
لأن إخفاءها يحرمه من معرفة أن أقرب أحلامه إليه يبعد ثلاث درجات. الشارة
الملوّنة تمنع الالتباس والمرشّح يترك له الخيار.

**س: ما الجديد الذي يقدّمه المحاكي؟**
كل ما قبله يجيب «هل أنا مقبول؟» وهو سؤال عن أمر لا يملك تغييره الآن.
المحاكي يجيب «ماذا أفعل؟» — يريه بأسمائها ما ينفتح له إن رفع معدله درجتين.
